<Tabs>
  <Tab title="Features">
    <CardGroup cols="2">
      <Card title="**Events that run themselves**" icon="calendar-clock">
        Weekly or one-off schedules in your time zone. A start missed while the server was down opens late with its original end, or is skipped. Warnings before closing, a reminder for players who join during an event, and a boss bar countdown. An open event survives restarts, and you can extend or shorten it while it runs.
      </Card>
      <Card title="**Personal, hidden offers**" icon="package-open">
        Six cards per player in the bundled menu, or as many card slots as you lay out. Rarities with weights, per-set limits and discount ranges; per-item weights, discounts and permissions. `preview` and `odds` show exactly what players can draw before you open the market.
      </Card>
      <Card title="**Rewards of every kind**" icon="sword">
        Vanilla items with full data components: name, lore, enchantments, item model, custom model data, glint, unbreakable, hidden tooltip parts. Any item in `/give` syntax. Custom items from ItemsAdder, Nexo, Oraxen and CraftEngine. Console commands, run exactly once per purchase.
      </Card>
      <Card title="**Vault and PlayerPoints**" icon="tool-case">
        Vault charges through the one economy plugin you name: EssentialsX, CMI, ExcellentEconomy and others. If another plugin takes over Vault, cards become unavailable instead of charging the wrong wallet. Each item picks its currency; PlayerPoints prices are whole points.
      </Card>
      <Card title="**Purchases that never charge twice**" icon="shield-check">
        Every purchase is recorded before and after the charge. If the server crashes mid-purchase, the purchase is held for review instead of retried, the player cannot be charged again, and staff are alerted. Every uncertain case has its own review command.
      </Card>
      <Card title="**A mailbox for full inventories**" icon="mailbox">
        A full inventory does not block a purchase: what does not fit waits in the mailbox, never expires, and is claimed with a click or `/ws mail`. Players with waiting rewards are told when they join.
      </Card>
      <Card title="**Your menus, sounds and words**" icon="languages">
        Menu size, card slots, icons and resource-pack item models. Every sound. Every message in MiniMessage, with English, Turkish, German, Spanish, French and Russian included.
      </Card>
      <Card title="**PlaceholderAPI**" icon="code-xml">
        Thirteen placeholders for scoreboards, TAB and holograms: open or closed, time left, the next opening, cards revealed and bought, the mailbox count. They read from memory, so they are safe from any thread.
      </Card>
      <Card title="**SQLite or MariaDB/MySQL**" icon="database">
        SQLite with no setup, or MariaDB 10.6+ and MySQL 8.0.16+. A daily SQLite backup, a backup before every schema update, and a cleanup job that never touches an unresolved money record.
      </Card>
      <Card title="**Tools for staff**" icon="slash">
        Status and diagnostics, odds and previews, a player's offers, mailbox and purchases, rerolls, a free `test give` to try rewards before an event, and clickable `/ws help` and `/ws admin help`.
      </Card>
    </CardGroup>

  <Tab title="Installation">
    <Steps>
      <Step title="Step 1">
        Download the resource from BuiltByBit or Polymart.

        <Note>
          Your server version should be **Paper 26.2+**
        </Note>
      </Step>
      <Step title="Step 2">
        You should install the necessary plugins before installing the resource.

        <Note>
          If you installed _necessary plugins_ before you don't need to do this step. Backup your configuration files before setup the configuration.
        </Note>
      </Step>
      <Step title="Step 3">
        Stop your server and make sure you meet the necessary requirements.
      </Step>
      <Step title="Step 4">
        Put the jar into `plugins/`**.**
      </Step>
      <Step title="Step 5">
        Start the server once, then stop it.\*\* \*\*WandererShop creates `plugins/WandererShop/`. With no license key yet it prints a framed `LICENSE VERIFICATION FAILED` block and turns itself off. That is expected.
      </Step>
      <Step title="Step 6">
        Set three values in `config.yml`\*\*. \*\*A name for this server, your economy plugin, and your license key:

        ```text
        server-id: "survival"                  # lowercase letters, digits, - and _; the license binds to it
        
        economy:
          vault:
            expected-provider: "Essentials"    # your economy plugin (see Economy setup)
        
        license:
          key: "WS-XXXX-XXXX-XXXX-XXXX"        # the key you received
        ```
      </Step>
      <Step title="Step 7">
        Start the server. The console shows `License verified` and `WandererShop ready`.
      </Step>
      <Step title="Step 8">
        Open your first market. Run `wanderershop admin event start 1h` in the console. Players open it with `/ws`.

        Next, make the offers your own in `pool.yml`, then run `/ws admin validate` and `/ws admin reload`. For automatic markets, turn on a schedule.
      </Step>
    </Steps>
  </Tab>
  <Tab title="Commands">
    `/wanderershop` also answers to `/ws` and `/wshop` (`commands.aliases`). `/ws help` shows each player the commands they may use; anyone with an admin permission also gets `/ws admin help`. Every command in those lists is clickable: one that only shows something runs, one that changes something goes into the chat box first.

    > **For Players:**

    | **Command** | **Permission** | **What it does** |

    | /ws about | wanderershop.use | Version, developer and website. |
    | /ws help | any of the above | The commands you may use, clickable. |

    ### **Offers only some players can draw**

    Give an item a `permission` in `pool.yml` and only players with that permission can draw it. The name is yours to choose, so VIP ranks can get offers no one else sees:

    ```yaml
    master_pack:
        rarity: epic
        price: { currency: vault, amount: 30000 }
        permission: "wanderershop.pool.vip"   # checked when the player's set is made
    ```

  <Tab title="Licenses">
    Your purchase comes with a license key, `WS-XXXX-XXXX-XXXX-XXXX`. WandererShop checks it once, at startup.

    - Put the key into `license.key`, or into the `WANDERERSHOP_LICENSE` environment variable.
    - **The first start binds the key to your** `server-id`**.** Choose it before that start and keep it. To move to another server, ask the seller to release the key.
    - If the license server cannot be reached, the last confirmed license keeps working for up to seven days.
    - Only the key, the `server-id`, the plugin version and the server port are sent. No player data.
    - `/ws admin license` shows who it is licensed to and when it ends. You can also check a key at [ronix-plugins.vercel.app](http://ronix-plugins.vercel.app).

    | **The console says** | **Do this** |
    | --- | --- |
    | no license key | Set `license.key` and restart. |
    | unknown license key | Copy the key again, exactly. |
    | license is bound to another server-id | Use the `server-id` you started with first, or ask the seller to release the key. |
    | license expired, license revoked | Contact the seller. |
    | server unreachable | Allow outbound HTTPS to [ronix-plugins.vercel.app](http://ronix-plugins.vercel.app) and restart. |
