<Tabs>
  <Tab title="Offers">
    `pool.yml` decides what the merchant sells: rarities, items, prices and rewards. The bundled file is a working example to start from.

    <Warning>
      **The one rule to remember:** an event freezes `pool.yml` when it opens. Changes apply from the next event. To change a running event: `event stop confirm`, edit the file, `validate`, `reload`, `event start`.
    </Warning>

    ### Rarities

    Rarities color the hidden cards, limit how many of each a player can get, and set the discount range. These five ship with the plugin; rename, recolor, add or remove them freely.

    | **Rarity** | **Weight** | **Discount** | **Per set** | **Reveal (sound)** |
    | --- | --- | --- | --- | --- |
    | Common | 100 | 0–15% in 5% steps | at most 4 | pling |
    | Uncommon | 60 | 5–20% | at most 3 | chime |
    | Rare | 30 | 10–30% | at most 2 | amethyst chime |
    | Epic | 15 | 15–35% | at most 1 | level up |
    | Legendary | 5 | 20–40% | at most 1 | challenge complete<br />(announced to the server) |

    Weight belongs to each item: a rarity with many items shows up more often overall. `/ws admin odds` prints the real chances, and `validate` warns about items with less than a 0.5% chance.

    ### An Item

    ```yaml
    items:
      dragon_sword:                      # id: a-z, 0-9, _ ; never rename or reuse it
        rarity: epic
        weight: 12                       # optional, overrides the rarity's weight
        price: { currency: vault, amount: 20000 }
        discount: { min: 15, max: 35, step: 5 }   # optional; 0 = never discounted
        rewards:
          - item:
              material: netherite_sword
              name: "<gradient:#ff5555:#ffaa00>Dragon Sword</gradient>"
              lore: ["<gray>Forged with a dragon's breath."]
              enchantments: { sharpness: 5, fire_aspect: 2, unbreaking: 3 }
              item-model: "minecraft:netherite_sword"
              custom-model-data: { strings: ["dragon"] }
              glint: true
              unbreakable: true
              hide-tooltip: [enchantments, unbreakable]
          - item: { material: golden_apple, amount: 3 }
    ```

    ### Rewards

    ```yaml
    rewards:
      - item: experience_bottle                                   # one unit
      - item: { material: diamond, amount: 4 }
      - item: { give: "minecraft:potion[potion_contents={potion:'minecraft:strong_swiftness'}]", amount: 3 }
      - item: "itemsadder:myns:dragon_sword"                      # custom item
      - item: { key: "nexo:ruby", amount: 3, name: "<red>Ruby" }
      - command: "lp user {uuid} parent addtemp vip 7d accumulate"
        description: "VIP rank (7 days)"                          # shown on the card
    ```

    - **Commands** run from the console after the charge and the items, in order, exactly once per purchase, even if the server crashes. Only `{player}` `{uuid}` `{event_id}` `{offer_id}` `{purchase_id}` `{item_id}` are filled in.
    - Use `{uuid}` for plugins that accept it (LuckPerms). Vanilla commands need `{player}`; write them as `minecraft:experience add {player} 10 levels` so no other plugin's command runs instead.
    - An item whose command is not installed cannot be bought, and nobody is charged. Try every command reward with `/ws admin test give <item> <yourself> confirm` before the event.

  <Tab title={"Events & Schedules"}>
    Open a market by hand with `/ws admin event start [duration] [offers]`, or let schedules do it. Times are in `locale.timezone`.

    ```yaml
    schedules:
      weekend:
        enabled: true
        type: weekly                 # weekly | once
        days: [FRIDAY]               # MONDAY..SUNDAY; an empty list means every day
        time: "20:00"
        duration: "3d"               # Friday 20:00 to Monday 20:00
        offers-per-player: 6         # optional
      halloween:
        enabled: true
        type: once
        at: "2026-10-31T20:00"
        duration: "48h"
    ```

    - The bundled examples ship turned off. After a change: `validate`, then `reload`; `/ws admin event schedule` lists the next five openings.
    - If the server was down at the start time, `event.late-start: open-late` opens it late with its original end; `skip` skips that one.
    - Warnings before closing (`1d`, `1h`, `10m`, `1m` by default) are sent once per event, even across restarts. The last ones also show a title and play a sound.
    - The boss bar appears in the last hour by default; its color and style are yours to set.
    - Players who join during an event get a reminder with a clickable `[Open]`.
  </Tab>
  <Tab title="Economy">
    WandererShop charges Vault prices through one economy plugin, and you name it. If another economy plugin takes over Vault, the currency becomes unavailable and the reason is printed: no one is charged from a wallet you did not choose.

    1. Run `wanderershop admin debug` in the console.
    2. Among the `Vault economy` lines, the highest priority wins, for example `owner=Essentials · priority=Normal`.
    3. Write that owner name into `economy.vault.expected-provider` and run `wanderershop admin reload`.
    4. `wanderershop admin status` then shows `Currency vault: ready · Essentials`.

  <Tab title="Purchase Safety">
    Every purchase is written to the database before the money moves and again after. The balance is checked before and after the charge, so an economy plugin that takes a different amount is caught. A player can never buy an offer twice, and a crash never charges anyone twice.

    When the server cannot know for sure what happened, for example a crash at the exact moment of payment, the record is held for review instead of being retried. The player's card shows "Under review" and staff with `wanderershop.admin.alerts` get an alert.

    - `/ws admin reconcile list` shows everything awaiting a decision; `status` shows the counts.
    - The player is told the decision exactly once: right away if online, otherwise on their next join.
    - Outcomes that cannot reach the database while the server stops are kept in a journal file and written at the next start.
  </Tab>
  <Tab title="Mailbox">
    With `purchase.inventory-full: mailbox` (the default), a full inventory does not stop a purchase. The confirm screen warns how many stacks will not fit; after payment they go to the mailbox. With `refuse`, a purchase that does not fit is turned down before payment.

    - Players claim with `/ws mail` or the mailbox button in the market menu, up to `mailbox.claim-batch` rewards at a time.
    - Rewards in the mailbox never expire: they are paid goods.
    - Players with waiting rewards get a clickable `[Claim]` when they join.
    - Staff see any player's mailbox with `/ws admin mailbox <player>`.
  </Tab>

  <Tab title={"Menus, Sounds & Languages"}>
    - **Menus** (`config.yml → gui`): rows, card slots, the timer, mailbox and close buttons, the frame and fill. Every icon takes a `material` and an optional resource-pack `item-model`. Slots count from 0 (row × 9 + column) and accept ranges such as `"10-16"`.
    - A broken `gui` section is rejected as a whole: `reload` keeps the last valid layout and `validate` says why.
    - **Hidden cards** take their look from the rarity: `card: { hidden-material, hidden-item-model }`. With `gui.show-rarity-when-hidden: false` they hide their rarity too.
    - **Sounds** are written as `"key volume pitch"`, for example `"minecraft:block.bell.resonate 1.0 1.0"`. Resource-pack sounds work; `""` is silent.
    - **Messages** live in `lang/<language>.yml` and use MiniMessage; `<prefix>` works in every message. English, Turkish, German, Spanish, French and Russian ship with the plugin; pick one with `locale.language`.
  </Tab>
  <Tab title={"Storage & Backups"}>
    **SQLite** is the default and needs no setup: the data lives in `plugins/WandererShop/wanderershop.db`. For **MariaDB 10.6+ or MySQL 8.0.16+**, create an empty database and set `storage.type: mariadb`; WandererShop creates its tables. Use one database per server.

    ```yaml
    storage:
      type: mariadb
      mariadb:
        host: "db.example.net"
        port: 3306
        database: "wanderershop"
        username: "wanderershop"
        password: "a-long-random-password"
        parameters: ""               # MySQL without SSL: "allowPublicKeyRetrieval=true"
    ```

    - **SQLite backups** go to `plugins/WandererShop/backups/`: one before every schema update, and one a day after the cleanup job, the last seven kept. They are consistent copies, safe while the server runs.
    - For MariaDB or MySQL, back up with `mariadb-dump --single-transaction` or `mysqldump`.
    - Keep `secret.key` with your backups: it makes every player's hidden offers unpredictable.

    ### Cleanup

    Five minutes after startup and then once a day, old data is removed. Nothing that belongs to a purchase under review or an undelivered reward is ever deleted.

    | **Setting** | **Default** | **Removes** |
    | --- | --- | --- |
    | `retention.closed-event-offers` | 60d | Unbought offers of closed events |
    | `retention.delivered` | 90d | Delivered or cancelled rewards |
    | `retention.audit` | 365d | Audit records |
    | `retention.purchases` | 0 | Completed purchases; `0` keeps them forever |
    | `retention.journal-replayed` | 90d | Replayed journal files |
  </Tab>
